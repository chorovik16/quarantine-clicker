# 🎮 Quarantine Multi-Account Automation Bot

> **Автоматизований багатопотоковий клікер та сторожовий бот (Watchdog) для браузерної MMO гри [Quarantine](https://quarantine-game.ru/) з комп'ютерним зором, автономним відновленням та віддаленим керуванням через Telegram.**

---

## 📌 1. Яку задачу вирішує проєкт (Problem Statement)

Проєкт створено для усунення щоденної монотонної рутини (гринду) та оптимізації ігрового прогресу одночасно на **4+ акаунтах** без блокування роботи користувача за комп'ютером.

### Основні виклики та їх вирішення:
* **Рутинний цикл фарму**: Гра вимагає постійного повторення послідовностей (вхід у сховище «Домик», чергування натискань `1` та `Space` для роботи/збору ресурсів). Бот виконує цей цикл автоматично з чітко вивіреними таймінгами.
* **Мультиакінг без блокування ПК**: Стандартні рішення (AutoClicker, звичайний PyAutoGUI) керують фізичним курсором миші та клавіатурою ОС — через це користувач не може користуватися комп'ютером, а запуск більше ніж одного вікна стає неможливим. Наш бот запускає кожен акаунт в окремому ізольованому браузерному інстансі з власними сесіями та незалежним керуванням.
* **Автоматичний менеджмент ресурсів (Енергія та Припаси)**: У процесі гри персонаж витрачає енергію. Бот автономно розпізнає стан виснаження, відкриває інвентар, обирає потрібний відновлювальний напій і повертається до роботи.
* **Автономність 24/7 та самолікування (Watchdog)**: Браузерні ігри часто стикаються з витоками оперативної пам'яті (memory leaks), мережевими мікророзривами чи зависаннями інтерфейсу. Бот забезпечений дворівневим механізмом захисту від зависань (активний watchdog за часом неактивності + планове періодичне оновлення сторінки).
* **Віддалене сповіщення та зворотний зв'язок**: Якщо закінчилися припаси або вичерпано всі відновлювальні напої, оператор миттєво отримує сповіщення в Telegram і може відновити роботу бота в один клік зі смартфона через Telegram Inline Button після поповнення запасів.

## 🏗 2. Архітектура та декомпозиція задачі (Architecture & Decomposition)

Архітектуру проєкту спроєктовано за модульним принципом з чітким розділенням обов'язків (Separation of Concerns):

```
┌─────────────────────────────────────────────────────────────────────────┐
│                    GUI Layer (Tkinter Desktop Panel)                    │
│      Відображення статусів акаунтів [СТАРТ / СТОП / ЖДУ ТГ / ...]       │
└──────────────────┬─────────────────────────────────┬────────────────────┘
                   │                                 │
                   ▼ (thread-safe events)            ▼
┌──────────────────────────────────────┐  ┌───────────────────────────────┐
│ Async Worker Thread (AsyncIO Loop)   │  │ Telegram Polling Thread       │
│                                      │  │ (Long-polling / getUpdates)   │
│  ┌────────────────────────────────┐  │  │                               │
│  │ GameBot (Account #1 .. #N)     │  │  │ Слухає inline callbacks       │
│  │  • Playwright Persistent Ctx   │  │  │ від адміна (resume_{id})      │
│  │  • Game State Machine Logic    │  │  └──────────────┬────────────────┘
│  │  • OpenCV Vision Engine        │  │                 │
│  │  • 120s Watchdog Timer         │  │                 │
│  └────────────────────────────────┘  │                 │
└──────────────────┬───────────────────┘                 │
                   │ (asyncio.run_coroutine_threadsafe)  │
                   └─────────────────────────────────────┘
```

### 🧩 Компоненти системи:

1. **Графічний інтерфейс користувача (GUI Layer — `ControlPanel`)**:
   * Побудований на базі Tkinter / ttk.
   * Працює в головному потоці ОС (Main Thread).
   * Дозволяє оператору візуально бачити стан кожного підключеного акаунта та запускати/зупиняти їх незалежно.

2. **Модель паралелізму та синхронізації (Concurrency & Threading)**:
   * **Main Thread**: Відповідає виключно за рендеринг GUI та обробку взаємодії користувача.
   * **Asyncio Thread (`_start_async_thread`)**: Фоновий потік із власним Event Loop, у якому працюють асинхронні екземпляри `GameBot` через `asyncio.gather`.
   * **Telegram Listener Thread (`_tg_listener`)**: Окремий фоновий потік, що виконує синхронний long-polling Telegram Bot API без блокування інтерфейсу чи ігрових дій.
   * **Thread-safe взаємодія**: Для передачі подій між потоками використовуються `loop.call_soon_threadsafe()` (оновлення кнопок інтерфейсу з асинхронного коду) та `asyncio.run_coroutine_threadsafe()` (передача команди відновлення з Telegram у чергу asyncio).

3. **Браузерний рушій (Browser Automation — Playwright)**:
   * Використовує асинхронний API Playwright (`async_playwright`).
   * Для кожного акаунта створюється ізольований постійний контекст (`launch_persistent_context`) у директорії `./game_profiles/account_{id}`. Це зберігає авторизаційні cookies, local storage і кеш, виключаючи необхідність повторного логіну.
   * Кожен браузерний інстанс закріплено за окремим портом віддаленого налагодження (`--remote-debugging-port=9220 + id`).
   * Перед запуском автоматично видаляється `SingletonLock` для захисту від блокування після аварійного закриття.

4. **Комп'ютерний зір (Computer Vision — OpenCV & NumPy)**:
   * Знімок екрана сторінки захоплюється безпосередньо з пам'яті (`page.screenshot()`) без зайвих операцій запису на диск.
   * Буфер декодується через `np.frombuffer` та `cv2.imdecode`.
   * Алгоритм зіставлення шаблонів: `cv2.matchTemplate` з нормалізованим коефіцієнтом кореляції `cv2.TM_CCOEFF_NORMED`.
   * Адаптивні пороги впевненості (`confidence`):
     - `0.75` для кнопок навігації та іконок інвентарю;
     - `0.90 – 0.92` для критичних статусних вікон («Закінчилися припаси», «Немає енергії»), що унеможливлює хибні спрацьовування.

5. **Система самовідновлення (Resilience & Watchdog)**:
   * **Hang Detector (120 с)**: Якщо час між останніми результативними діями перевищує 2 хвилини (зависання анімації, втрата вебсокета, лаг сервера), бот ініціює перезавантаження сторінки `page.reload()`.
   * **Global Reload (3600 с)**: Планове перезавантаження раз на 1 годину для очищення витоків пам'яті браузера.

6. **Телеметрія та зворотний зв'язок (Telegram Bot API)**:
   * Надсилання сповіщень через асинхронний HTTP-клієнт `httpx.AsyncClient`.
   * Інтерактивні Inline-кнопки (`callback_data="resume_{id}"`), які запускають процедуру м'якого рестарту акаунта (`_resume_sequence`) після вирішення проблеми гравцем.

## 💡 3. Самостійно прийняті інженерні рішення (Key Decisions Made Independently)

| Рішення | Обраний підхід | Альтернатива (і чому від неї відмовилися) |
|---|---|---|
| **Інструмент автоматизації** | **Playwright Async** | *PyAutoGUI / Selenium*. PyAutoGUI повністю захоплює фізичну мишу/клавіатуру, що робить неможливим мультиакінг у фоні. Selenium важчий за накладними витратами, гірше масштабується на 4+ паралельні профілі з асинхронним циклом подій. |
| **Детекція елементів інтерфейсу** | **Комп'ютерний зір (OpenCV)** | *DOM / CSS / XPath селектори*. Графіка та елементи керування у грі рендеряться на Canvas або мають динамічні обфусковані селектори. Шаблонне розпізнавання OpenCV забезпечує 100% стійкість до оновлень коду розмітки. |
| **Ієрархія відновлення енергії** | **Дворівнева стратегія (Fallback)** | *Простий клік або аварійна зупинка*. Реалізовано пріоритет: 1) пошук «Енергетика» (`drink.png`) з подвійним підтвердженням (`1` x2); 2) якщо немає — автоматичний пошук «Квасу» (`kvas.png`) з одинарним споживанням; 3) тільки якщо напої повністю вичерпано — перехід у режим очікування і Telegram-алерт. |
| **Фоновий режим без перехоплення уваги** | **Аргумент `--no-focus-on-new-window`** | *Стандартний запуск Chromium*. Запуск 4 вікон Chromium за замовчуванням кожні кілька хвилин перехоплює системний фокус вікон ОС Windows, заважаючи друкувати або працювати в інших програмах. Спеціальні прапорці усувають цю проблему. |
| **Двостороннє керування через Telegram** | **Inline-кнопки відновлення** | *Тільки одностороннє логування*. Замість того, щоб змушувати користувача підходити до комп'ютера, бот надає можливість натиснути «Продолжить ✅» у Telegram-боті після дозакупівлі речей через мобільний телефон. |
| **Безпека облікових даних** | **Конфігурація через змінні оточення (`.env`)** | *Хардкод токенів у вихідному коді*. Використання `python-dotenv` захищає токен бота та `ADMIN_ID` від випадкового витоку в публічний репозиторій. |

## 🛠 4. Стек технологій (Tech Stack)

* **Мова програмування**: Python 3.10+
* **Браузерна автоматизація**: [Playwright (Async API)](https://playwright.dev/python/)
* **Комп'ютерний зір та обробка зображень**: [OpenCV (opencv-python)](https://opencv.org/), [NumPy](https://numpy.org/)
* **Мережеві запити**: [HTTPX](https://www.python-httpx.org/) (Async & Sync)
* **Графічний інтерфейс**: Python Tkinter / ttk
* **Месенджер інтеграція**: Telegram Bot API (Inline Keyboards & Callbacks)
* **Керування конфігурацією**: `python-dotenv`

## 🚀 5. Встановлення та запуск (Installation & Setup)

### 1. Клонування репозиторію
```bash
git clone https://github.com/ВАШ_НІКНЕЙМ/quarantine-multibot.git
cd quarantine-multibot
```

### 2. Створення та активація віртуального оточення
```bash
# Windows:
python -m venv .venv
.\.venv\Scripts\activate

# Linux / macOS:
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Встановлення залежностей
```bash
pip install -r requirements.txt
playwright install chromium
```

### 4. Налаштування змінних оточення
Створіть файл `.env` на основі наданого шаблону:
```bash
cp .env.example .env
```
Відкрийте `.env` і вкажіть ваш Telegram Bot Token та ID адміністратора:
```ini
TG_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
ADMIN_ID=987654321
GAME_URL=https://quarantine-game.ru/
NUM_ACCOUNTS=4
```

### 5. Підготовка шаблонів розпізнавання (Шаблони OpenCV)
Розмістіть знімки цільових ігрових елементів у кореневу директорію або папку `templates/`:
* `button_home.png` — іконка/кнопка входу в «Домик»
* `drink.png` — іконка енергетика в рюкзаку
* `kvas.png` — іконка квасу в рюкзаку
* `no_energy.png` — модальне вікно / статус закінчення енергії
* `no_supplies.png` — модальне вікно / статус закінчення припасів

### 6. Запуск програми
```bash
python kar.py
```
* Відкриється панель керування Tkinter із кнопками для кожного з 4 акаунтів.
* Браузери відкриються з окремими профілями; після першого ручного входу в гру сесії зберігаються автоматично.
* Натисніть **«СТАРТ #1»** (або відповідний акаунт) для запуску автономного циклу.
